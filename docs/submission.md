## 1. 動くものを公開する（バックエンド担当と一緒に）

- [ ] Firebase Hosting に公開する（README の「公開（Firebase Hosting）」の手順）。担当：＿＿
  - GitHub の Settings → Secrets and variables → Actions で、変数 `FIREBASE_PROJECT_ID` と、シークレット `FIREBASE_SERVICE_ACCOUNT` を登録すると、`main` に push するたびに自動で公開される
  - 変数 `DEV_TOOLS` は**登録しない**（開発用ボタンが出てしまう）
- [ ] 公開された URL を iPhone の Safari で開き、「タップして準備」→ 振って記録できることを確かめる
- [ ] バックエンドとつながった機能があれば、`docs/product.md` の「機能と実装状況」を「予定」から「実装済み」に書き換える

- [ ] 予算アラートを設定する（通知されるだけで、自動では止まらない）

> 実行基盤の必須条件（App Engine・Compute Engine・GKE・Cloud Run・Firebase App Hosting・Firebase Hosting のどれか 1 つ以上）は、Firebase Hosting で満たす。

## 4. 提出用リポジトリにコピーする

運営の提出用リポジトリ（`df-2026-t071`）に、このリポジトリの**最新のファイルだけ**をコピーする。履歴ごとはコピーしないので、昔のコミットに何か残っていても公開されない。
たとえると、下書きノートを丸ごと渡すのではなく、清書した最新ページだけを提出箱に入れるイメージ。

自分の Mac のターミナルで、`protein-kanpai` のフォルダにいる状態から:

```bash
git pull
```

```bash
git clone https://github.com/Devfest-Hackathon-2026/df-2026-t071.git ../df-2026-t071
```

```bash
scripts/export-to-submission.sh ../df-2026-t071
```

スクリプトがやること：

- コミットしていない変更や、鍵らしいファイル（`.env`、`*service-account*.json` など）があれば止まる
- アプリ一式を提出用リポジトリの `app/` に置く
- 提出用リポジトリの `README.md` の**先頭**に、アプリの案内（動画・説明・図へのリンク）を入れる。運営が書いた部分は消さない
- 提出用リポジトリでコミットする（push はしない）

GitHub で見える形を確認してから push する:

```bash
cd ../df-2026-t071 && git log --oneline -3 && git status
```

```bash
git push
```
